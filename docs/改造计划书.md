# 方块纪元 · 改造计划书

## 1. 现状诊断

**现有内容**：纯前端像素沙盒（`index.html` / `style.css` / `game.js` ≈ 2500 行单文件 IIFE），48×36 地图，四个职业（矿工/农夫/法师/骑士），流程为「白天采集 → 夜里守篝火 → 撑过两夜 → 献祭方块之心」。已有静态契约测试、Playwright e2e、GitHub Pages 自动部署。

**为什么"乏味"**

| 问题 | 表现 |
| --- | --- |
| 目标单一、一次性 | 只有"撑两夜"一个胜利条件，通关即结束，没有重玩动机 |
| 地图固定 | 每局一样，探索无惊喜 |
| 成长扁平 | 资源需求固定（木4/石5/金3/麦3），无升级、无构筑选择 |
| 职业差异小 | 差别主要在数值，缺少改变玩法的机制 |
| 无社交/分享 | 没有成绩、没有对比，无传播点 |
| 无长期留存 | 无存档、无解锁、无日常目标 |
| 受众模糊 | 说不清给谁玩 |

## 2. 目标受众与定位

**一句话定位**：*"五分钟一局的像素生存 Roguelite——每天一张全球相同的地图，和朋友比谁守得更久。"*

| 受众 | 需求 | 对应设计 |
| --- | --- | --- |
| 碎片时间的休闲玩家（学生/上班族） | 开局快、5–10 分钟一局、无需注册 | 网页即开即玩、短局制 |
| 像素/生存/塔防爱好者 | 构筑深度、策略 | 随机事件、升级三选一、职业专精 |
| 社交分享型玩家 | 可晒成绩、可约战 | 每日挑战种子、成绩卡片、种子分享链接 |
| 手机玩家 | 触屏操作 | 虚拟摇杆 + 自动攻击 |

## 3. 改造愿景与核心循环

```
选职业 + 选"祝福/诅咒" → 白天探索/采集/建造 → 夜袭（随机怪潮+Boss）
   → 夜后三选一升级 → 更难的下一夜 → 死亡/通关 → 结算、解锁、分享
```

由"通关一次"变为"**无尽夜晚 + 局外成长**"：目标从"撑两夜"改为"撑得越久分越高"，原两夜通关保留为"新手教程模式"。

## 4. 改造内容（按支柱）

### 支柱 A：Roguelite 化（解决"一次性"）
1. **随机地图**：基于种子的程序化生成（群系：森林/沙漠/沼泽/雪地，各有独特资源与怪）。
2. **夜后三选一升级**：如"栅栏带反伤""火把范围+""作物夜里也生长"等，约 30 张卡，分普通/稀有/传说。
3. **随机事件**：流浪商人、血月（怪物翻倍但掉落翻倍）、陨石（落下稀有矿）、迷雾夜。
4. **Boss 夜**：每 3 夜一个 Boss，各有机制（如：会拆栅栏的巨像、熄灭火把的幽灵）。
5. **无尽模式**：怪物强度按夜数曲线增长，记录"最高存活夜数"。

### 支柱 B：职业深度（解决"差异小"）
| 职业 | 新增核心机制 |
| --- | --- |
| 矿工阿石 | 可挖地下层（矿洞副本），带出稀有矿，换取永久解锁 |
| 农夫麦麦 | 驯养宠物/稻草人哨兵；作物联动加成 |
| 法师星萤 | 元素组合（火+风=火焰龙卷）；法力管理 |
| 骑士方盾 | 阵地防守：举盾格挡反击，守卫 NPC 招募 |
- 每职业 3 条专精分支（局内 / 局外解锁）。

### 支柱 C：建造与塔防（增强"玩出花样"）
- 新建筑：箭塔、陷阱、陶瓷灯、传送阵、围墙升级（木→石→砖）。
- 怪物 AI 分类：突击型、爬墙型、远程型、自爆型，迫使玩家改变布局。
- 篝火可升级（范围、回血、镇守光环）。

### 支柱 D：局外成长与留存
- **本地存档**（`localStorage`）：金币结算 → 解锁新职业皮肤、起手道具、卡牌池。
- **成就系统**：30 个左右（"一夜不受伤""只用火把通关"等）。
- **每日挑战**：当天统一种子 + 固定词缀，每日一次排行（本地 → 可选联网）。

### 支柱 E：社交与传播
- **成绩卡片**：结算时生成图片（Canvas 导出），含职业、存活夜数、种子、二维码/链接。
- **种子分享**：URL 参数 `?seed=xxxx&class=mage`，朋友点开即同图同条件。
- **排行榜**：先做本地/好友链接对比，再评估用 Serverless（如 Cloudflare Workers + KV）做全球榜。

### 支柱 F：视听与手感
- 角色立绘保留作为选人界面形象；游戏内增加像素动画帧（行走、攻击、受击）。
- 音效与 BGM（WebAudio 合成 chiptune，白天/夜晚/Boss 三套），可静音。
- 打击感：屏幕震动、击退、伤害飘字、夜幕过渡动画。
- **移动端适配**：虚拟摇杆、技能按钮、横竖屏。

### 支柱 G：新手体验
- 保留现有"撑两夜"作为 3 分钟引导关，带操作提示。
- 首次进入自动教学，后续可跳过。

## 5. 技术方案

| 项 | 方案 |
| --- | --- |
| 架构 | 将 `game.js` 拆为 ES 模块：`world`（生成）、`entities`、`combat`、`cards`、`events`、`ui`、`save`、`audio` |
| 构建 | 保持零后端、无框架；可引入 Vite 仅用于打包（可选），继续部署 GitHub Pages |
| 随机 | 自实现种子 PRNG（mulberry32），所有随机必须走它，保证每日挑战一致 |
| 数据驱动 | 卡牌/事件/怪物/建筑用 JSON 配置，便于扩展与平衡 |
| 存档 | `localStorage` + 版本号迁移 |
| 测试 | 扩展 `tests/static.mjs`（配置契约）、`tests/e2e.mjs`（种子可复现、存档读写）；新增确定性模拟测试（同种子同结果） |
| 性能 | 对象池、仅渲染视口、移动端目标 60fps |

## 6. 里程碑

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| **M0 重构（1 周）** | 模块化拆分，种子 PRNG，原有测试全绿 | 行为与现版一致，CI 通过 |
| **M1 可重玩核心（2 周）** | 随机地图、无尽夜、三选一升级（≥15 张）、结算页 | 一局 5–10 分钟，每局体验不同 |
| **M2 深度（2 周）** | 随机事件、Boss、怪物类型、新建筑、职业专精 | 4 职业各有明显不同打法 |
| **M3 留存（1 周）** | 存档、解锁、成就、每日挑战 | 关闭重开后进度保留 |
| **M4 传播（1 周）** | 成绩卡片、种子链接、移动端触控 | 手机可玩，可一键分享 |
| **M5 打磨与发布（1 周）** | 音效、动画、平衡、新手引导、README/截图/宣传 GIF | 公开发布 |

## 7. 成功指标

- 平均单局时长 5–10 分钟；
- 次日回访率 ≥ 20%（可用无隐私的本地计数 + 可选匿名统计评估）；
- 分享链接打开转化率；
- 玩家平均每人玩 ≥ 3 局。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 范围过大 | 严格按里程碑，每阶段可独立发布；砍功能优先级：F > E 排行榜 > C |
| 平衡难调 | 数据驱动配置 + 模拟测试批量跑数值 |
| 单文件重构回归 | M0 先重构不加功能，e2e 兜底 |
| 联网排行成本/作弊 | 先做本地+链接对比，联网放后期并做基本校验 |
| 美术资源不足 | 色块像素风 + 程序生成动画帧，保留四张立绘 |
