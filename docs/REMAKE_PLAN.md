# 方块纪元改造计划书 · 从「过关小品」到「值得一玩再玩的肉鸽守夜」

> 状态：计划书 v1 · 2026-10-27

## 1. 现状诊断：为什么"乏味"

现有版本（`game.js` 约 2500 行纯前端单文件，Canvas 渲染，无后端）是一个完成度不错的小品：

- 4 个职业（矿工/农夫/法师/骑士），属性与技能各异
- 白天采集、建造（栅栏/火把/农田），夜里 2~3 波怪守篝火
- 撑过 2 夜后献祭「方块之心」通关

但作为"游戏"它留不住人，核心问题：

| 维度 | 现状 | 问题 |
| --- | --- | --- |
| 重复可玩性 | 一局定胜负，通关即结束 | 没有成长沉淀、没有构筑差异、没有"再来一局"的理由 |
| 策略深度 | 资源配方固定（心=木4石5金3麦3） | 最优解唯一且很快被摸透，之后全是体力劳动 |
| 内容量 | 3 种敌人（史莱姆/蝙蝠/方块），1 张固定尺寸地图 | 10 分钟后无新内容 |
| 戏剧张力 | 波次数量写死，难度曲线线性 | 缺乏"啊这局完了"和"这也能翻"的瞬间 |
| 传播性 | 无成绩、无分享、无梗 | 玩家没有可以截图发给朋友的东西 |
| 技术结构 | 单文件 IIFE，状态挂在闭包 `state` 上 | 加任何系统都要在一个 2500 行文件里动刀，回归风险高 |

一句话：**它是个 demo，不是个游戏。** 玩家 15 分钟通关，永远不会再打开。

## 2. 改造愿景

**一句话定位：** 一款「白天经营构筑、夜晚肉鸽守塔」的浏览器小游戏——每局 20 分钟，局局不同，输了想复盘，赢了想晒分。

**三个设计支柱：**

1. **局局不同（Variety）**——随机地图生态、随机事件、遗物与变异，没有两局相同的夜。
2. **抉择有重量（Agency）**——每个白天只能做有限的事：多砍一棵树就少修一段墙。资源、时间、位置三重压力产生真正的策略。
3. **失败也精彩（Drama）**——可视化的惊险时刻（篝火 1% 血翻盘、Boss 破门而入），配合结算页的数据叙事，让每局都值得被讲述。

**受众定位：**

- 主受众：喜欢《吸血鬼幸存者》《环世界》式轻量策略的休闲玩家，摸鱼时间开一局（浏览器即开即玩是最大优势）
- 次受众：速通/挑战型玩家（每日种子、成就、难度阶梯）
- 传播渠道：GitHub Pages 直达链接 + 结算页一键复制战绩，零安装零门槛

**成功指标（可量化）：**

- 单局时长中位数 ≥ 15 分钟
- 玩家平均开局次数 ≥ 3（用 localStorage 匿名统计首屏展示，不上报）
- 通关率控制在 20~35%（有挑战但不劝退）

## 3. 玩法改造方案

按"核心循环 → 内容 → 元游戏"三层展开。

### 3.1 核心循环强化（P0）

**3.1.1 无尽模式 + 难度阶梯**

- 通关（献祭）不再是终点，而是「第一纪元」结束：玩家可选择【点亮祭坛 · 进入下一纪元】，夜数继续、敌人增强、解锁新敌种。
- 纪元 = 难度阶梯：每纪元 +1 夜数上限、敌人 HP/伤害 ×1.35、波次 +1、新机制（见 3.2）。
- 现有的 `WIN_NIGHTS = 2`、`spawnEnemy` 按 `state.nights` 分支的逻辑是天然的扩展点，改造成 `ERA` 驱动的配置表。

**3.1.1b 局内三选一（肉鸽精髓）**

- 每撑过一夜，天亮弹出「黎明的馈赠」三选一卡牌：
  - **遗物**（被动）：如「燧石斧：砍树 +50%」「风铃：敌人靠近篝火减速 30%」「矿工头灯：夜间视野 +1 格」
  - **祝福**（一次性/限时）：如「今夜狼群嚎叫：敌人自相残杀 10 秒」
  - **变异**（双刃剑）：如「血月契约：敌人 +40% 血，但掉落双倍」
- 这是把"乏味的固定最优解"打碎的核心机制。四职业 × 构筑流派才真正分化：农夫种田流、法师炮塔流、骑士堵门流。
- UI 复用现有 overlay 组件，数据驱动为 `RELICS` 配置表 + 加权随机。

**3.1.2 体力/行动点经济**

- 白天从"无限劳动"改为「日晷行动点」：砍树/挖矿/建造/修墙消耗行动点，点数 = 常量 + 遗物加成。
- 强迫玩家做取舍，这是策略感的来源。HUD 增加日晷图标。
- 注意：需配套「撤销/预览」与清晰的消耗提示，避免挫败感。

### 3.2 内容扩充（P1）

**3.2.1 敌人图鉴 ×2**

- 新增 4 种，每种对应一种玩家行为惩罚，逼玩家改变布防：
  - **掘地虫**：绕过栅栏挖地道直取篝火（克制纯围墙流）→ 解法：火把照亮范围内显形减速
  - **投石魔**：远程砸墙（克制龟缩流）→ 解法：骑士冲锋/法师点杀
  - **孢子花**：死后在原地生成腐蚀地块，农田减产（惩罚农集中摆放）
  - **纪元 Boss**：每纪元末夜出现（巨史莱姆王/暗影骑士），有多阶段与大字警报
- 敌人配置数据化：`ENEMIES = { slime: {...}, bat: {...}, ... }`，`spawnEnemy` 改为按纪元权重表抽取。

**3.2.2 地图生态与随机事件**

- `genWorld` 增加生态分区：晶洞区（金矿富集但有沉睡石像）、蘑菇林（夜晚发光、孢子怪）、乱石岗（免费石料）。
- 白天随机事件（每天 0~1 个）：商队路过（以物易物）、陨石坠落（限时挖矿点）、兽群迁徙（提前的小波次）。事件由 toast + 地图标记呈现。

**3.2.3 建筑与新配方**

- 新增：箭塔（石3金1，自动索敌）、尖刺（木2，踩上的敌人持续掉血）、仓库（资源上限）、圣泉（范围内缓慢回血）。
- 建筑体系从硬编码 `buildCost` 迁移到统一 `BUILDINGS` 表，为将来的"科技树/解锁"留口。

### 3.3 元游戏与传播（P1~P2）

**3.3.1 每日种子挑战**

- 用日期字符串做 PRNG 种子（`mulberry32` 之类），所有玩家同一天同一张图同一个事件序列，比拼撑过的夜数。
- 标题页加「今日挑战」入口；结算页生成一行文本战绩：`方块纪元·每日 1027 · 第4夜 · 击杀87 · 遗物[风铃,血月]`，一键复制。

**3.3.2 成就与图鉴（localStorage）**

- 12~16 个成就：单局不修墙通关、只用农田回血通关、篝火满血过夜、单夜击杀 30……
- 图鉴收录见过的敌人/遗物，未完成显示剪影。全部存 localStorage，纯前端无后端。

**3.3.3 视觉与音效升级**

- 屏幕震动/顿帧已有（`punch`），补充：受击方向指示器、Boss 登场演出、昼夜过渡的天空渐变层、粒子系统统一（现有 `burst` 扩展为配置驱动）。
- 音频：WebAudio 已够用，给每纪元一个和弦走向变化（现有 `playMusicPulse` 参数化）。

### 3.4 明确不做（Out of Scope）

- ❌ 多人联机 / 账号系统 / 后端排行榜（违背纯前端定位，维护成本爆炸）
- ❌ 更换引擎或引入框架（Canvas + 原生 JS 足够，重构 ≠ 重写）
- ❌ 付费点、广告（个人项目）
- ❌ 移动端专属适配（先做"能玩"，横屏提示，不做深度触控优化）

## 4. 技术实施方案

### 4.1 架构演进：渐进式拆分，不推倒重写

当前 `game.js` 是 IIFE 单文件。按以下顺序演进，每一步都可独立合并、独立通过 CI：

1. **配置外置（P0 前置）**：把 `CLASSES` / 敌人 / 配方 / 波次 / 遗物抽成 `data.js`（纯数据 ES module，`game.js` 改为 `<script type="module">`）。这是后续所有内容扩充的地基。
2. **系统拆分（P1 前置）**：按现有函数边界拆出模块——`world.js`（生成与地形）、`combat.js`（敌人/波次/伤害）、`build.js`（建造/农田）、`meta.js`（成就/种子/存档）、`ui.js`（HUD/overlay）。共享状态收敛为一个显式 `GameState` 对象。
3. **保留 `tests/static.mjs` 契约测试风格**：每加一个玩家可见规则，补一条契约（如 `ERA_SCALING = 1.35`）。e2e 增加「三选一出现并能选」「每日种子固定地图 hash」两个用例。

### 4.2 关键技术决策

| 决策点 | 方案 | 理由 |
| --- | --- | --- |
| 随机性 | 种子化 PRNG（mulberry32），按用途拆**多条独立随机流** | 每日挑战与"分享种子"的前提 |

**随机流拆分细则（回应审查意见）：**

现状是随机调用散布两处：`rand()` 内联 `Math.random()`（约 10 处调用），且 `spawnEnemy` 的敌种抽取、`updateEnemies` 的掉落判定等玩法逻辑**直接调用 `Math.random()`**；同时脚步声、粒子、屏幕震动等音画特效也消耗同一个 `rand()`。若共用一条流，每日事件序列会随玩家操作与特效调用而漂移，种子无法复现。

因此按用途隔离为四条流，各自持有独立种子状态：

| 流 | 用途 | 种子来源 | 迁移内容 |
| --- | --- | --- | --- |
| `rngWorld` | 地图生成（`genWorld`） | 每日种子 \| 随机种子 | 地形、资源分布 |
| `rngEvent` | 每日事件、波次构成、敌种抽取、掉落判定 | 每日种子 | 现散落的 `Math.random()`（敌种/掉落）全部迁入此流；只在这些**确定性时机**消耗，不受玩家操作影响 |
| `rngLoot` | 局内不可复现的战斗掉落微调 | 随机种子 | 允许每局不同，不进每日复现 |
| `rngFx` | 脚步声、粒子、屏幕震动、敌人 bob 相位 | 随机种子 | 音画表现，与玩法完全隔离 |

落地时把 `rand()` 改为 `rand(stream, n)`，全局替换直接 `Math.random()`；e2e 增加「固定种子 → 地图 hash 与事件序列一致」用例。

> 补充（M3-3）：出怪的格子是否可用取决于玩家建了什么，所以 `rngEvent` 的消耗次数仍会随打法漂移。现在三选一、每夜出怪、白天事件都改为按「种子 + 纪元 + 第几夜」现场派生一次性随机流（`nightRng("dawn")` / `nightRng("spawn")` / `dayRng()`），某一夜怎么打都不会影响下一夜的抽取。
| 存档 | localStorage，键名 `cube-epoch:v1:*`，版本号内置 | 纯前端约束下的唯一选择；版本号便于迁移 |
| 新内容加载 | 静态 import，不做动态加载 | 文件总量 < 100KB，Pages 托管无压力 |
| 平衡性调参 | 所有数值集中在 `data.js`，附 `BALANCE.md` 记录调参理由 | 让"调平衡"成为可审查的 PR |

### 4.3 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 拆模块引入回归 | 高 | 每步拆分单独 PR；e2e 必须先绿；拆分时只搬代码不改逻辑 |
| 内容膨胀导致平衡崩坏 | 中 | 每纪元敌人增强系数写入配置表；通关率埋点（本地统计面板）辅助调参 |
| 范围失控、永远做不完 | 高 | 严格按 P0→P1→P2 交付，每个里程碑都是"可发布的完整游戏" |
| 种子化后现有测试 flaky | 低 | 测试注入固定种子 |

## 5. 里程碑与落地路线

> 不估人日，只排依赖顺序。每个里程碑结束即走 ship-gate 流程（测试 → review → PR → CI → Pages）。

### M0 · 地基（P0）
1. `rand()` 种子化 + `data.js` 配置外置（无行为变化）
2. 黎明的馈赠：遗物/祝福/变异三选一系统（首批 12 个遗物）
3. 无尽模式 + 纪元难度阶梯
4. 结算页战绩文本 + 一键复制

**出口标准：** 通关后可进入第二纪元；每夜结束有三选一；`npm test` 全绿。

### M1 · 内容（P1）
5. 4 种新敌人 + 纪元 Boss（数据驱动 spawn 表）
6. 日晷行动点经济
7. 新建筑（箭塔/尖刺）+ 地图生态分区
8. 模块拆分（world/combat/build/ui）

### M2 · 传播（P2）
9. 每日种子挑战 + 图鉴/成就
10. 白天随机事件
11. 视觉音效升级、平衡性调参轮
